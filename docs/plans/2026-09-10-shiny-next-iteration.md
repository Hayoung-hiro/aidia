# 전체 적용 범위를 중심으로 한 다음 UX 작업

## 이번에 반영한 내용

사용자가 실제 데이터로 슬라이더 미리보기·확정 결과 보존·Reset의 정상 동작을 확인했다. 추가 피드백에 따라 m/z preview의 첫 선택을 **All RT groups**로 바꿨다.

- 전체: RT(가로축)–m/z(세로축) 평면에 전체 validated precursor의 밀도와 전략별 선택 범위를 겹친다. 처음 구현한 합산 histogram + window 지도를 사용자 피드백에 따라 교체했다.
- 리포트의 `plot_density_with_mz_range()` 밀도 표현을 재사용한다. 밝은 색은 높은 밀도, 초록색 테두리는 각 RT 구간의 선택 범위다. 리포트의 중간점 연결선 대신 실제 RT 시작·끝을 표시한다.
- 요약: 전체 RT 그룹 수·precursor 수·window 폭 범위·기존 전체 coverage.
- 개별 RT 구간을 선택하면 기존 KDE 곡선·threshold·구간 지표로 전환한다.
- 전체 분포는 범위 선택 전 데이터로 계산하여 선택 범위 밖의 분포도 보인다. 밀도 그림은 background worker에서 준비하며, 보기 전환으로 다시 계산하지 않는다.
- 범위 선택은 RT별로 이루어지므로 전체에 단일 KDE threshold나 단일 선택 범위를 표시하지 않는다.
- 보기 선택은 계산 설정과 분리된다. 설정을 바꿔도 전체 선택은 유지되고, RT 재분할로 선택했던 구간이 없어지면 전체로 돌아간다.

작업 파일: `preview_worker.R`, `preview_display.R`, `server_live_preview.R`, `ui_step2_setup.R`, `app.R`.

검증: Shiny 구문 검사, `shiny-live-preview` 테스트 통과. 밀도 layer가 리포트와 같고 선택 범위를 바꿔도 유지되는지, 각 테두리가 실제 RT/m/z 범위와 일치하는지 검증했다. Edge에서 전체/개별 전환, threshold 변경, RT 재분할 시 선택 복구, staggered 모드, 390px 배치, 조회 범위 전환 후 확정 CSV의 byte 동등성을 확인했다. 검토용 합성 데이터 12,000개를 사용했으며 실제 실험의 성능 검증은 아니다.

## 다음 작업 단위: 확정 대비 변화 요약 + 전체에서 상세로 이동

현재의 세 구획, 슬라이더, 항목 옆 도움말을 유지한다. 설명 문단이나 큰 KPI 카드를 추가하지 않고 기존 미리보기 안에서 판단을 돕는다.

### 1. 확정 결과 대비 변화 요약

**목적:** 파라미터 변경이 전체 설계에 어떤 영향을 줬는지 즉시 판단한다.

- 기존 요약 값 옆에 마지막 확정 결과 대비 차이를 표시한다.
- 첫 지표는 전체 window coverage, window 폭의 대표값·범위, 실제 DPPP 중앙값으로 제한한다.
- coverage 변화는 percentage point로 표시한다. 여러 RT 구간 coverage를 평균해 전체 지표로 사용하지 않는다.
- 증가를 무조건 초록색 성공으로 표시하지 않는다. coverage와 window 폭 사이의 절충을 판단할 수 있도록 방향과 수치를 중립적으로 표시한다.
- 동일 데이터의 확정 결과가 있을 때만 비교한다. 미리보기 계산 중에는 이전 차이를 현재 값처럼 보여주지 않는다.

**완료 기준:** 확정→슬라이더 변경→Reset 흐름에서 차이가 해당 계산 snapshot과 일치하고, Reset으로 확정 상태를 복원하면 차이가 0이 된다. 확정 전에는 비교 표시가 없다. CSV 기준은 그대로 유지된다.

### 2. 전체 지도에서 관심 RT 구간으로 이동

**목적:** 전체를 보고 궁금한 부분만 자세히 확인한다.

- 지도에서 RT 구간을 선택하면 dropdown과 개별 미리보기가 함께 바뀐다.
- 전체 보기로 돌아가는 동작을 한 번에 제공한다.
- 작은 화면에서는 기존 dropdown도 계속 사용할 수 있게 한다.
- 지도에서 선택하는 것은 보기 변경이며 RT grouping 설정을 바꾸지 않는다.

**완료 기준:** 클릭·dropdown이 같은 구간을 가리키고, 설정 변경·최적화 재실행·확정 상태 변경 없이 상세 표시만 바뀐다. RT 재분할 후 존재하지 않는 선택은 전체로 복구한다.

구현 시 RT–m/z 평면의 가로축 클릭 좌표를 해당 RT 구간에 연결한다. 현재 그림은 worker에서 grob로 준비하므로 Shiny 클릭 좌표 변환을 위한 plot 좌표 정보 전달도 함께 구현한다.

## 후속 작업 순서

| 순서 | 작업 | 필요성·범위 |
|---|---|---|
| 3 | 결과가 제한되는 이유 표시 | 최소 inclusion 조건, 적은 precursor에 따른 density fallback, 폭·digitization 제약 등 실제 계산 경로를 짧은 상태로 보여 준다. 설명은 `?`에 둔다. |
| 4 | 살펴볼 RT 구간 표시 | 실제 구간별 window coverage나 폭 분포를 근거로 관심 구간을 지도에서 표시한다. 범위 inclusion과 최종 window coverage를 구분하고, 판정 기준을 설명할 수 있어야 한다. |
| 5 | 데이터 규모에 따른 갱신 성능 개선 | 실제 데이터에서 planning·RT 분할·KDE·window 생성·그림 준비 시간을 측정한 뒤 재사용할 중간 계산을 결정한다. 최근 요청 우선과 확정 결과 보존을 유지한다. |

3번은 계산 진단 정보를 전달하는 변경이 필요하다. 화면 값을 보고 원인을 추측해 표시하지 않는다. 알고리즘의 결과를 바꾸지 않는 진단 정보 추가와 기존 결과 동등성 검증을 별도 작업으로 다룬다.

이번 요청에서는 전체 보기를 구현하고 여기까지 계획했다. 다음 작업 단위와 후속 항목은 아직 구현하지 않았다.
