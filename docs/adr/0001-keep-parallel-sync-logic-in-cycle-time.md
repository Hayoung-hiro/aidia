# Keep parallel-instrument sync logic inside `cycle_time.R`

When splitting the legacy `R/instrument_utils.R` into focused modules (v0.4.1), we considered extracting the parallel-architecture functions — `calculate_duty_cycle_sync()`, `calculate_sync_optimal_windows()`, `resolve_astral_ms1()` — into their own `R/astral_sync.R`. We decided against it: these functions are the parallel branch of cycle time math, and `calculate_cycle_time_from_experiment()` already dispatches between sequential and parallel internally, so splitting would scatter one concept across two files. Per the seam discipline rule **"two adapters = real seam"**, parallel currently has one adapter (Astral) — Bruker TimsTOF and SCIEX ZenoTOF are planned but not yet verified. Revisit this decision when a second parallel instrument is implemented; until then, sync logic stays in `cycle_time.R`.
